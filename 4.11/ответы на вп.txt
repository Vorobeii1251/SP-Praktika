1. Для чего используется встроенный модуль node:net?
Это базовый модуль Node.js для работы с TCP‑сокетами. С ним можно создавать серверы и клиентов, управлять соединениями, читать и писать данные, обрабатывать события и ошибки — без сторонних библиотек.

2. Чем отличаются net.createServer и net.createConnection?

net.createServer(callback) — для сервера: он ждёт подключений, а когда кто‑то подключается, callback создаёт сокет для общения с этим клиентом.
net.createConnection(options, listener) — для клиента: он сам инициирует подключение к серверу, и когда соединение установлено, срабатывает listener.
Простыми словами: сервер «слушает», клиент «стучится».
3. Для чего сервер вызывает listen?
server.listen(port, host) говорит ОС: «Зарезервируй этот порт на этом адресе и принимай входящие TCP‑подключения». Без этого сервер не сможет принимать клиентов.

4. Какое событие позволяет получить данные из TCP‑соединения?
Событие data на объекте сокета:

js
socket.on('data', (chunk) => {
  console.log('Получены данные:', chunk);
});
Оно срабатывает каждый раз, когда в поток приходят байты.

5. Что делает socket.write?
Отправляет данные в TCP‑поток. Например:

js
socket.write('ACK: Ваше сообщение\n');
Важно: это асинхронная операция — данные могут уйти не мгновенно, но в итоге попадут к получателю.

6. Почему клиент получает ECONNREFUSED, если сервер не работает?
Потому что никто не слушает указанный порт. Клиент пытается установить TCP‑соединение, ОС видит, что на этом порту нет слушателя, и явно отклоняет соединение — Node.js получает ошибку ECONNREFUSED.

7. Что означает EADDRINUSE?
«Address already in use» — адрес (IP:порт) уже занят другим процессом. В TCP один и тот же порт на одном адресе может слушать только один процесс, поэтому второй экземпляр сервера не может запуститься и падает с этой ошибкой.

8. Почему нельзя считать, что каждое событие data содержит ровно одно сообщение?
TCP — это поток байтов, а не протокол сообщений. Сетевой стек может:

разбить одно сообщение на несколько частей (несколько событий data),
или объединить несколько сообщений в один кусок (одно событие data).
Поэтому в реальных приложениях сообщения нужно явно разделять (например, по символу \n, по длине, по заголовкам) — иначе нельзя надёжно определить границы сообщений.s
